## Notes
- Visitors who used the app before this change have saved state under `evelo:v2` but no `evelo:v2:entered` flag, so they see the landing once at the bare URL ([returning-user-without-flag.txt](returning-user-without-flag.txt)). This follows the flag-based rule, and no check covers it. If they should go straight to the planner, `readEntered` could also count existing `evelo:v2` state as entered.
- After a share link opens, the hash is rewritten to `#outlook`. That behaviour predates this stage, and the flag is set as expected.
- The unit tests cover `resolveRoute` and the flag module. The store wiring (`initial()`, `setRoute` → `markEntered`, `bareEntered` for Back) has no unit test; the browser runs above cover it.

## After the review fix (PM, 2026-11-07)
The returning-user note was fixed: on the first read on a device, `readEntered` counts a plan saved before the flag existed (`evelo:v2`) as having entered, and records the answer at once (`'1'` or `'0'`), so a plan saved later from the landing (theme toggle) never counts. The flag now reads `'0'` (not missing) for a visitor who hasn't entered; `drive.cjs`'s two "flag unset" assertions were changed to `!== '1'` to match.
